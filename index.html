For one Mac running Tailscale alongside a second VPN—corporate or commercial.

Run your VPN and Tailscale at the same time on a Mac.

When your VPN connects, MagicDNS stops resolving and peers time out. tailroute watches the routing table and makes the call for you: internet through the VPN, peers through the mesh. It undoes itself when the VPN disconnects.

CLI daemon

$brew install shrwnsan/tap/tailroute-cli The full engine, Apache-2.0, as a root launchd daemon. After it installs, run sudo tailroute install, connect your VPN as usual, then run tailroute status and watch it make the call.

Menu bar app

$brew install --cask shrwnsan/tap/tailroute The same engine behind a menu bar icon. Includes the CLI. The app isn’t notarized yet. The first time you open it, macOS asks you to approve it in System Settings → Privacy & Security → Open Anyway. Open Tailroute, connect your VPN as usual, then run tailroute status and watch it make the call.

Uninstall restores everything, including MagicDNS. The daemon has no account and no telemetry.

How it works

A daemon that makes the call, so you don’t.

Every routing-table change lands in one of three states, and the response is always the same. You do nothing.

Three states, zero judgment calls
Condition MagicDNS Proxy on 127.0.0.1:1055
Tailscale and your VPN are both active off up
Tailscale only on stopped
No Tailscale unchanged unchanged (keeps watching)

If the state is ambiguous — two VPNs active at once, say — tailroute logs a warning and changes nothing. When in doubt, do nothing.

When the VPN connects—on hotel or café Wi-Fi, this is your Tuesday.

Every peer times out.

SOCKS5 mesh proxy

A tsnet-based proxy on 127.0.0.1:1055 routes peer traffic through the mesh even when the VPN blocks the CGNAT range. Starts and stops with the VPN—never configured by you. Helpers included: sshproxy, curlproxy, generated SSH config.

When you need a peer’s dashboard

Cert warnings, extensions, luck.

Browser tunnels

One command registers a launchd-managed tunnel and maps a managed /etc/hosts entry— a valid, real .ts.net certificate in Safari, Chrome, or Firefox. Adaptive path: SOCKS5 when the VPN is up, direct when it isn’t.

Honest limits

What it can’t fix

Told up front, not discovered later.

tailroute works with any VPN that takes the default route—whatever VPN you’re forced to run. What varies is whether that VPN also blocks Tailscale’s address range (100.64/10) at a layer below the routing table. This is everything we know so far, with the evidence for each row:

VPN compatibility, with the evidence for each row
VPN DNS fix Direct peer traffic Workaround Evidence
Mullvad Works at the DNS layer: DNS resolved normally with Mullvad connected alone, and failed only in the Mullvad + Tailscale exit-node combination. Blocked—Mullvad’s Network Extension drops packets to 100.64/10 under every tested setting: split tunnel enabled, per-app exclusions, Allow LAN enabled. tsnet SOCKS5 proxy (validated while the VPN is active); disconnect Mullvad when mesh access is needed; Mullvad exit nodes purchased through Tailscale (single tunnel); SSH to a peer’s public IP (fails if the peer firewall allows only 100.64/10). Not viable: Tailscale exit node alongside Mullvad (DNS and SSH both fail); mullvad tunnel set allowed-ips excluding 100.64/10 (breaks Tailscale entirely). Tested
NordVPN not recorded Blocked on all tested protocols: NordLynx (auto) and OpenVPN UDP and TCP, with Threat Protection ON or paused. NordLynx’s AllowedIPs (0.0.0.0/1, 128.0.0.0/1) cover all IPv4 including CGNAT, and the Threat Protection system extension stays enabled even when the feature is paused in the UI. No NordVPN-specific setting found. General workarounds apply: tsnet SOCKS5 proxy (validated against Network Extension blocking), disconnect NordVPN for mesh access, SSH to a peer’s public IP. Tested

Network Extensions can still block the mesh

Modern macOS VPN apps intercept all outbound traffic—including packets to Tailscale’s CGNAT range (100.64/10). tailroute fixes the DNS conflict and can bridge peers through its proxy, but it cannot bypass Network-Extension packet interception. When direct mesh traffic is blocked, use the SOCKS5 proxy or a browser tunnel.

Also on the record

  • While the VPN is active, MagicDNS names don’t resolve—reach peers by their 100.x address or through a tunnel.
  • Firefox DNS over HTTPS bypasses the managed /etc/hosts entries, so tunnel names stop resolving in Firefox.
  • Out of scope, decided after Phase 0 research: MagicDNS split DNS while on a VPN, multiple simultaneous VPNs, and IPv6.

FAQ

Asked, answered

Can I use Tailscale and my VPN at the same time on a Mac? +
Yes—that’s exactly what tailroute does. When your VPN connects, the daemon toggles MagicDNS off and brings up a local SOCKS5 proxy, so internet flows through the VPN while peers stay reachable through the mesh—and it reverses itself when the VPN disconnects. Any VPN that takes the default route works; VPNs that also block Tailscale’s CGNAT range at the packet level (Mullvad, NordVPN) still need that proxy or a tunnel for direct peer traffic—next question covers those.
Does it work with Mullvad or NordVPN? +
The DNS fix works—internet stays up through the VPN with Tailscale connected. But both VPNs block direct traffic to Tailscale’s CGNAT range at the Network-Extension layer, so direct peer connections fail; use the built-in SOCKS5 proxy (automatic) or a browser tunnel instead. Details in the compatibility notes.
What about corporate VPNs—Cisco AnyConnect, GlobalProtect, Zscaler? +
The daemon classifies routing changes from any VPN that takes the default route—no per-VPN plugins, no allowlists. The DNS conflict is fixed automatically either way; if the corporate client also blocks the CGNAT range at the Network-Extension layer, the same proxy-and-tunnel path bridges your peers.
Which Tailscale install does it need? +
The CLI daemon (brew install tailscale) is fully supported—tailroute toggles DNS over its unix socket. The GUI app works with limitations (fall-back MagicDNS detection), and the Mac App Store version is not supported.
Why does macOS ask me to approve the app the first time it opens? +
The app isn't notarized yet. The first time you open it, macOS asks you to approve it in System Settings → Privacy & Security → Open Anyway. The CLI daemon installs without this step.
Does it phone home? +
No. The daemon has no telemetry, makes no external network calls, and needs no account. It never intercepts or logs your traffic. The only network activity is the proxy and tunnels you configure, pointing at your own tailnet.
It runs as root—why should I trust it? +
Because it shows its work: sudo tailroute install writes a SHA-256 manifest of the installed files. The daemon checks it before loading any code and refuses to start if anything changed. Strict input validation, absolute paths only, MagicDNS restored when the daemon stops. The whole thing is ~8,300 lines of auditable bash and Go (8,096 sh + 217 Go, wc -l, Nov 2026). Prefer the manual? Read the full man page—shipped with this site.
What happens when I quit the VPN or uninstall? +
VPN disconnects → MagicDNS is restored automatically (within seconds of the route change, with a 60-second safety check for anything missed). Uninstall restores MagicDNS state, removes the daemon, tunnels, and hosts entries—and preserves logs for review.
Who is tailroute for—and who is it not for? +
For one Mac running two networks at once: Tailscale alongside a second VPN—the corporate client (Cisco AnyConnect, GlobalProtect, Zscaler), a commercial privacy VPN (NordVPN, ProtonVPN, Surfshark), or a travel setup where hotel Wi-Fi meets your tailnet. Not for: Tailscale-only setups—if Tailscale is your only VPN or exit node, there is no conflict to manage—and Tailscale’s Mullvad exit-node add-on, which already solves coexistence inside Tailscale. Also out of scope: MagicDNS split DNS while on a VPN, multiple simultaneous VPNs, IPv6.
What’s the best way to run Tailscale and a VPN together on a Mac? +
There are two working approaches. If your privacy VPN is Mullvad, Tailscale’s Mullvad exit-node add-on is the first-choice route—buy it inside Tailscale and skip a second app. For every other VPN (NordVPN, ProtonVPN, Surfshark, corporate clients), run tailroute alongside your VPN: it fixes the DNS conflict automatically and bridges peers through a local proxy when the VPN blocks Tailscale’s address range. Other paths—gluetun containers, VPS bridges, travel routers—work but demand constant upkeep.
