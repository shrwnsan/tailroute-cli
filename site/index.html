[event] route change detected

One daemon. Three states. Zero decisions left for you.

Every routing-table change is classified into one of three states — and the response is always the same, deterministic move.

COEXIST

Tailscale + VPN active

MagicDNS off · SOCKS5 proxy up. Internet flows through the VPN; peers stay reachable through the mesh proxy on 127.0.0.1:1055.

MESH

Tailscale only

MagicDNS on · proxy stopped. Full MagicDNS name resolution and direct mesh access, exactly as Tailscale intended.

IDLE

No Tailscale

Nothing happens. The daemon stays quiet, keeps watching, and never touches settings it doesn’t own.

⚠ Ambiguous state — say, two VPNs at once? The daemon logs a warning and does nothing. Fail-safe first, by design.

[info] capabilities

More than a DNS toggle

watch

Live route watching

Event-driven via route monitor, with a 60-second safety-net re-assert that self-heals out-of-band changes. Toggles are idempotent — no flapping, no redundant writes.

mesh

SOCKS5 mesh proxy

When a VPN blocks Tailscale’s CGNAT range, a tsnet-based proxy on 127.0.0.1:1055 routes traffic through the mesh anyway. Auto-starts and auto-stops with the VPN.

browse

Browser tunnels

Open a peer’s Tailscale Serve dashboard in Safari, Chrome, or Firefox — with a valid, real .ts.net certificate. No extensions, no cert warnings.

config

SSH & shell helpers

tailroute proxy-config ssh and … shell generate ready-to-paste config — sshproxy mypeer and curlproxy http://… just work.

integrity

Self-verifying install

A SHA-256 manifest written at install time is verified before any library loads. Tampered files? The daemon refuses to start — and tells you what changed.

privacy

Private by construction

No telemetry, no external network calls, no account, no traffic inspection or logging. It’s your Mac; tailroute just watches the routing table.

[tunnel] add mypeer --port 8443

Your peer’s dashboard, in any browser, with valid TLS.

One command registers a launchd-managed tunnel, maps a managed /etc/hosts entry, and hands you a bookmarkable URL. It keeps working whether the VPN is up or not — the path adapts automatically (SOCKS5 when the VPN is active, direct when it isn’t).

$ tailroute tunnel add mypeer
✓ ssh auth ok · peer reachable · port free
✓ serve backend accepting · TLS cert valid
✓ /etc/hosts entry + launchd job registered
→ https://mypeer.yourtailnet.ts.net:8443

$ tailroute tunnel check mypeer
✓ hosts → listener → TLS → HTTP 200
  transport: tunnel+tls ok · backend: serve ok

Three read-only verbs, three different questions: status = the inventory · drift = the peer’s claim · check = the browser’s truth.

  • Hardened contract. Valid TLS is mandatory at add — a mismatched cert rolls the whole thing back. Every step is journaled before it runs, so a crash can’t leave half a tunnel behind.
  • Transactional updates. Adding a second --remote-port forward updates the running job in place; on any failure the previous healthy job is restored.
  • Per-forward health. tunnel status reports listener, backend, and TLS state for every forward — and a 502 behind a valid certificate is reported as what it is: the peer’s service is down, not the tunnel.
  • Machine-wide safety. The /etc/hosts edit is serialized with a hosts lock, so two users’ tunnel operations can never interleave.

[warn] ambiguity encountered — reporting honestly

What tailroute can’t fix

We’d rather tell you now than have you find out later. Modern macOS VPN apps use Network Extensions that intercept all outbound traffic — including packets destined for Tailscale’s CGNAT range (100.64/10). tailroute fixes the DNS conflict; it cannot bypass packet interception.

Tested VPNs that block mesh traffic

VPNProtocols testedCGNAT blocked
MullvadWireGuardyes
NordVPNNordLynx · OpenVPN · NordWhisperyes

Some older VPN implementations let mesh traffic through. Report your VPN’s behavior ↗

Known trade-offs

  • While the VPN is active, MagicDNS names don’t resolve — use 100.x IPs, or add a browser tunnel.
  • Firefox with DNS-over-HTTPS bypasses /etc/hosts — Safari and Chrome use the system resolver.
  • Tunnel URLs carry a non-standard port (:8443-style) — port 443 would need root.
  • Won’t-fix by research: MagicDNS split-DNS, multi-VPN support, IPv6. The fail-safe is safer.

Runs as root. Acts like it.

A root daemon earns scrutiny. tailroute is hardened accordingly — and the threat model, audit results, and hardening details are all public.

Integrity gate

An install-time SHA-256 manifest is verified before any library is sourced. Mismatch means refuse-to-start, not degrade-and-continue.

Strict validation

Interface names must match utun\d+; IPs are CIDR-validated against 100.64/10; every system call uses absolute paths.

Fail-safe defaults

When state is ambiguous the daemon does nothing. No guesswork in a tool that flips system DNS settings.

Minimal surface

No traffic interception, no logging of network content, no external calls, no signing up for anything. Ever.
